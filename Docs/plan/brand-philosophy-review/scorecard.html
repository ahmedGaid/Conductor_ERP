The rubric — the 8 Conductor Standard

Every screen is scored against these. Each is re-asked as a yes/no decision question; any honest "no" becomes a finding. The set is typed and ordered — the numbering is the Standard's own.

1
Invisible complexityOne obvious thing, one primary action. Hide depth, never omit it.
2
Instant performanceFeels immediate. No spinner where cached data could paint. Saving is invisible.
3
Calm by defaultMonochrome chrome. Colour only inside the work, paired with a word or icon.
4
Trust through transparencySays what happens before, reassures after. Reversible.
5
Consistency everywhereThe same action behaves the same on every screen.
6
Human AINotices, explains, protects. Drafts-only and gated. N/A where there's no AI.
7
Craft in every detailType, spacing, motion, Arabic language, errors — all feel designed.
8
Business confidenceThe user leaves every screen more informed and more in control.

P1 — break · fails the ship test P2 — off-brand · noticeable, not blocking P3 — polish · small craft debt Pass — on-brand as-is Pending — not yet reviewed
03

Systemic findings — known now

Three findings the QA audit surfaced before the per-screen pass. Each is app-wide, so it seeds the scorecard rather than living in one surface. Fix ownership already assigned in the queue.

P1 · global

No app-wide error boundary

Any uncaught render error white-screens the entire app with no recovery path — the one state the brand forbids being left undesigned.

Fails Standard 4 (reassure after) + 7 (every error state designed) · owner: pre-handover-hardening/FILE_03
P2 · global

Most routes are not code-split

The router eagerly imports ~40 page components, enlarging the first-paint bundle. In tension with "feels instant" on cold load, especially on modest hardware.

Tensions Standard 2 (instant performance) · candidate finding · Session A
P2 · Session H

E-invoice status copy must not claim live ETA submission

The ETA adapter is currently simulated. Any UI string that reads as "submitted to the Tax Authority" would over-promise — a transparency and claims-discipline breach.

Fails Standard 4 + Brief §12 claims discipline · decision: pre-handover-hardening/FILE_01

How each session runs

  1. Recall conductor-brand (the rubric + Arabic lexicon) and erp-frontend (what "normal" looks like) before touching a screen.
  2. Run the app (run-dev.ps1, login admin/Dev12345!). Drive every screen in the surface — no scoring from screenshots alone.
  3. Ask the 7 decision questions honestly per screen. Every "no" is a finding: screen · verdict · Standard(s) failed · severity · the specific fix.
  4. Check the Arabic against Identity §6 — one canonical word per concept, human status, blame-free error. This is where craft slips most often.
  5. Check both themes (light + dark) and both directions (RTL + LTR read identically).
  6. Append findings to this scorecard. Do not fix in the review pass — fixes become their own sessions, ranked by severity.
