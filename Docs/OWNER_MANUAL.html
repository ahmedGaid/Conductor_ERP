    The big picture

    Conductor is being built like a house: foundations first, then floors, then the things guests see. This manual explains the full engineering roadmap — 13 areas of work ("domains") — in plain words, so you can follow, question, and approve work without reading code.

    The one rule that governs everything: the live queue in Docs/plan/EXECUTION_ORDER.md decides what gets built today. This roadmap is the reservoir — the complete map of everything that must eventually exist. Small "floor" tasks (standards, security, testing) slot into gaps; big domains open only when their entry gate opens (e.g. multi-tenant work waits for the SaaS phase of the Founder Plan).

    Why 13 domains and not a single to-do list

    Each domain is a different kind of risk. Core ERP protects correct money. Security protects trust. DevOps protects "it still works tomorrow". A flat list hides which risk you're buying down; domains make it visible. Every domain below tells you: what it is, why it matters, what good and bad look like, the common traps, and how to review each finished task.

    How to use this manual

    Search box (top-left) filters everything live. Checkboxes next to tasks are your personal progress tracker — they save in this browser only; the real source of truth is the Status: line inside each roadmap file. Chips like gate: SaaS phase mean the task waits for a business milestone. Task IDs like D5.P1.T1 mean Domain 5, Phase 1, Task 1 — quote the ID when you ask an engineer or AI session "where are we on this?"

    Your weekly ritual (15 minutes): open this page → Progress summary → for anything marked done since last week, run its "How you review" line. If a review fails, the task was not done — say so plainly.

    How you review any task — the universal 5 questions

    1. Show me. Ask for a live demo in the app (Arabic first), not a description. No demo = not done.
    2. Show me it failing safely. Ask "what happens when it goes wrong?" — the error must be polite Arabic, blame-free, and tell the user what to do next.
    3. Show me the gates. Ask for the gate-run output (the automated checks). All green, pasted, dated.
    4. Show me the test that would catch it breaking later. Every fix/feature leaves a tripwire behind.
    5. Would Linear ship this? Your standing taste question. If your gut says no, trust it.

    Every task below adds ONE specific check on top of these five.
